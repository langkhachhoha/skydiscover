# CORAL stress-test tasks

The two "stress test" tasks of the CORAL paper (Qu et al., COLM 2026,
arXiv:2604.01658), set up so the skydiscover baselines (`openevolve_native`,
`gepa_native`, `adaevolve`, `evox`) and SpecEvo are all scored by the same
code. The launcher is `scripts/server/run_pk_queue.sh`.

| task | what | score (higher is better) | reference points |
|---|---|---|---|
| `polyominoes/` | Frontier-CS algorithmic #0, "Pack the Polyominoes (Reflections Allowed)": C++17, 70 tests, 2 s CPU / 256 MB each | 0..100, mean of the checker's per-case ratio | CORAL 4 agents w/o web 84.2; SOTA 87.0 |
| `kernel_builder/` | Anthropic's VLIW SIMD tree-traversal take-home | 147734 / cycles (speed-up over the naive kernel) | official best 1363 cycles = 108.4; CORAL 4 agents 1103 = 133.9 |

## Files

- `polyominoes/judge.py` — local re-implementation of the Frontier-CS judge
  (same compiler flags, limits, testlib exit-code rule and `Ratio:` parsing,
  score = 100 × mean ratio), so no Docker / go-judge is needed. Problem data,
  checker and testlib come from a Frontier-CS checkout (`$FRONTIER_CS_DIR`,
  set up by `scripts/server/setup_coral.sh`). Mechanics are tested in
  `tests/test_polyomino_judge.py`.
- `polyominoes/initial_program.cpp` — the empty skeleton CORAL starts from.
- `kernel_builder/frozen_problem.py`, `kernel_builder/initial_program.py` —
  copied unchanged from CORAL `examples/kernel_builder/{taskdata,seed}` at
  commit 0123dfb (Apache-2.0).
- `kernel_builder/kernel_eval.py` — CORAL's grader loop (forest_height 10,
  16 rounds, batch 256, 8 correctness runs), split in two processes: the
  candidate only builds the instruction list (passed on as JSON), and a clean
  interpreter that never runs candidate code simulates it — so a candidate
  cannot monkeypatch the simulator or the reference, which CORAL's own grader
  would allow.
- `*/evaluator.py` — skydiscover evaluators; `*/config.yaml` — generated by
  `make_configs.py` (gpt-5 via OpenRouter, the CORAL task text as the system
  prompt). Edit `make_configs.py` and re-run it rather than the YAML.
- SpecEvo versions: `levi/examples/polyominoes/problem.py` (the candidate is
  Python whose `solution()` returns the C++ source; judged identically) and
  `levi/examples/kernel_builder/problem.py`.
